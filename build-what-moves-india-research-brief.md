# Executive summary

Build What Moves India asks builders to choose one real friction point in an Indian public-service digital journey and build a simpler, clearer, end-to-end prototype. The target is not a cosmetic redesign: the prototype must address the underlying process, backend or integration assumptions, and operational feasibility.

Codex is mandatory and must be a meaningful part of the submitted prototype. The official pages explicitly prohibit connecting to or interfering with live government systems, using sensitive or real user data, reverse-engineering private systems, or implying official government endorsement.

# The challenge

Pick one real problem you have personally encountered on an Indian public-service website or digital service. Examples named by the official brief include travel, taxes, pensions, certificates, payments and grievances, with IRCTC, EPFO and the Income Tax portal offered only as examples—not a fixed list.

## A compliant, strong prototype

* Solve one clearly defined user problem and let reviewers complete the main journey end-to-end.
* Make the journey easier to understand or use than today, including for mobile users, slower connections, and people with limited digital experience.
* Use mock or synthetic data anywhere a real system, payment, OTP or personal information would normally be required.
* Make clear what works, what is mocked, and how the solution could safely operate at scale.
* Explain the backend, infrastructure and process changes needed; a cleaner interface layered over the same broken process is insufficient.
* Use Codex meaningfully in building the prototype and explain its contribution.

# Non-negotiable safety, data & IP rules

| Do not | Required approach |
| --- | --- |
| Access, test, or interfere with a live government system | Build an independent simulation; only use an organizer-approved public sandbox if one is specifically provided. |
| Reverse-engineer private systems; use undocumented private APIs; scrape personal/restricted information | Use public understanding of the journey and describe assumed integrations at a high level. |
| Use real Aadhaar, PAN, passwords, OTPs, payment details, health data or other sensitive personal information | Use fictional/synthetic data only. Never enter real credentials or identifiers. |
| Present the prototype as an official product or use logos to imply approval/partnership | Clearly label it as an independent hackathon prototype; avoid misleading official branding. |
| Submit an old project with only minor changes, or include material without usage rights | Make the submission for this hackathon; disclose starter templates/open-source components and respect their licences. |

# Submission package

Deadline: 27 August 2026. Every submitted link must work without requesting reviewer access.

* Live demo link.
* Short demo video, ideally no longer than 3 minutes.
* Short write-up: the problem; who it affects; solution and changes; why it is better; tools used and Codex contribution; what is functional vs mocked; known limitations.
* Source-code repository or reviewer-access link (optional).

The FAQ sets a high bar for the demo: every feature shown must actually work. Figma/design work may support the submission but is not enough by itself; the main journey must be a working prototype.

# Practical entry checklist

* Write a one-sentence problem statement tied to a real user and one specific journey.
* Document the current failure, its user impact, and the deeper process/operational cause.
* Build only an independent prototype using mock APIs and synthetic data; keep a visible “independent prototype” label.
* Define the end-to-end happy path and make every demonstrated step work.
* Record all mocked steps, assumptions, limitations, dependencies, third-party libraries and how Codex materially contributed.
* Prepare a focused <=3-minute demo: problem → journey → why it is better → what is real/mocked → how it could scale safely.
* Validate every shared link in a signed-out/reviewer-like browser session before submission.
